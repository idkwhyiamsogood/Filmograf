# Filmograf

Мобильное приложение для тех, кто много смотрит кино: каталог фильмов, оценки,
подборки, история просмотров и обсуждения — в одном месте, с акцентом на
быстрый и «нативный» по ощущениям интерфейс.

## Цели

- **Найти, что посмотреть.** Каталог с фильтрами и сортировкой, полнотекстовый
  поиск, персональная лента рекомендаций, похожие фильмы, топы.
- **Вести свою фильмотеку.** Оценки, история, избранное, собственные подборки
  с тегами; чужие подборки можно закрепить или скопировать к себе.
- **Обсуждать без страха спойлеров.** Древовидные комментарии к фильмам и
  подборкам с форматированием и **спойлерами** — скрытый текст, который
  раскрывается только по нажатию. Для приложения про кино это обязательная
  функция, а не украшение.
- **Ощущаться как нативное приложение.** Шторки (bottom sheet) вместо
  модалок, жесты, оптимистичные обновления, системная тема и акцентный цвет,
  нативный сплэш при запуске.
- **Пускать сразу.** Смотреть можно без регистрации — вход нужен только для
  действий: оценить, прокомментировать, собрать подборку.

## Структура репозитория

```
backend/    микросервисы на .NET 8 + docker-compose с инфраструктурой
frontend/   клиент: React 19 + Vite, упакованный в Capacitor (Android)
```

## Backend

Набор независимых сервисов за nginx-шлюзом (`backend/shared/nginx.config`
маршрутизирует `/api/<сервис>/…`). Общий код — в `BaseLibrary`
(доступ к данным, кэширование, интеграции через шину).

| Сервис | Ответственность |
| --- | --- |
| `AuthService` | Вход через Google, гостевые (временные) токены, пользователи |
| `MoviesService` | Фильмы, жанры, оценки, лента |
| `CommentsService` | Комментарии и реакции к фильмам и подборкам |
| `CollectionsService` | Подборки, теги, закрепления |
| `SearchService` | Поиск (Elasticsearch), live-поиск через SignalR |
| `SearchIndexerService` | Индексация обновлений фильмов в Elasticsearch |
| `ParsingService` | Сбор данных о фильмах из внешних источников |
| `AnalyticsService` | Клики/просмотры, персональные рекомендации |

**Инфраструктура** (`backend/docker-compose.yml`): PostgreSQL и MongoDB —
хранилища, Redis — кэш, RabbitMQ — асинхронная связь между сервисами,
Elasticsearch (+ Kibana) — поиск. Swagger всех сервисов собирается в один хаб.

**Решения:**

- **Сервис на ограниченный контекст.** Комментарии, подборки, поиск и т. д.
  деплоятся и масштабируются отдельно; межсервисное взаимодействие идёт
  событиями через RabbitMQ (например, результат парсинга расходится в фильмы
  и поиск).
- **Поиск вынесен в отдельный индекс.** Elasticsearch обновляется
  индексатором по событиям, чтобы тяжёлые запросы не нагружали основные БД.
- **Кэш на чтение** в Redis для горячих данных (ленты, корневые комментарии,
  подборки) с инвалидацией при изменениях.

## Frontend

React 19 · TypeScript · Vite · TanStack Router (файловый роутинг) ·
TanStack Query · Tailwind CSS 4 + shadcn/ui · Lexical · Capacitor 7.

### Ключевые решения

- **Capacitor вместо отдельного нативного клиента.** Один код для веба и
  Android; нативные возможности — через плагины: `@capacitor/preferences`
  (настройки), `@capacitor/clipboard` (ссылки из буфера),
  `@capacitor/splash-screen`, Google Auth.
- **Серверное состояние — только TanStack Query.** Кэш, пагинация
  (infinite queries), инвалидация при входе/выходе. Мутации оптимистичные:
  комментарий, оценка или пин появляются сразу, при ошибке откатываются.
- **Гостевая сессия по умолчанию.** Бэкенд требует токен, поэтому при первом
  запуске клиент молча получает гостевой и сразу показывает контент; вход
  через Google предлагается в момент действия, которому он нужен.
- **Комментарии хранятся как сериализованное состояние Lexical (JSON).**
  Это даёт форматирование и спойлеры без своего формата разметки и без
  HTML-санитайзинга. Спойлер — собственный inline-узел `SpoilerNode`
  (`shared/components/lexical/nodes`): в редакторе текст виден и помечен, в
  ленте скрыт до нажатия. Старые комментарии простой строкой тоже читаются.
- **Шторки и модалки через единый реестр** (`shared/contexts/modal-context`):
  открываются по имени из любого места, включая код вне React (обработчик
  ошибок axios через `modalBridge`).
- **Оформление.** Режим темы (системная/светлая/тёмная) и акцентный цвет
  (палитры в OKLCH или «цвет дня») хранятся в Preferences и применяются до
  первого кадра — без вспышки темы по умолчанию. В шторке «Оформление»
  изменения копятся в черновике и применяются кнопкой «Сохранить».
- **Экран загрузки.** При холодном старте ОС сразу показывает нативный
  сплэш `@capacitor/splash-screen` в цвет приложения — он закрывает WebView,
  пока грузится JS. Как только отрисован анимированный постер, нативный
  сплэш плавно уходит, и постер держится до готовности сессии. Постер
  показывается один раз за сессию (процесса приложения или вкладки
  браузера) — перезагрузка (F5, live reload) его не вызывает.
- **Иконка** рисуется в SVG (`frontend/assets/icon`: фон, буква F и
  собранная иконка) и нарезается скриптом `bun run icons` во все размеры:
  adaptive- и монохромная иконки Android (`mipmap-*`), favicon, apple-touch-icon
  и иконки PWA-манифеста (`public`). Править нужно только SVG.
- **Моки API.** Axios-адаптер с in-memory базой (`shared/lib/mock`) позволяет
  разрабатывать интерфейс без поднятого бэкенда; по умолчанию включён,
  выключается `VITE_USE_MOCKS=false`.

### Архитектура кода

Сейчас код разложен по слоям в духе FSD (`app`, `entities`, `features`,
`widgets`, `shared`, `routes`). Запланирован переход на **модульную
архитектуру**: модуль — обособленная предметная область (`catalog`,
`comments`, `appearance`, …), модули могут использовать друг друга через
публичное API.

```
src/
  modules/
    <module>/
      services/    запросы TanStack Query, сгруппированы по сущности:
                   <entity>/keys.ts, <entity>/<action>.ts, index.ts
      context/     React-контексты модуля
      hooks/       хуки декомпозиции/контекстов/UI (не запросы к API)
      types/       доменные сущности, DTO, адаптеры
      ui/          виджеты модуля: <widget>/index.ts + его компоненты
      components/  переиспользуемые компоненты внутри модуля
      index.ts     всё, что доступно за пределами модуля
  shared/          общий UI-кит, утилиты, http-клиент
  routes/          страницы (TanStack Router)
```

## Запуск

Backend:

```bash
cd backend && docker compose up -d
```

Frontend (веб):

```bash
cd frontend && bun i && bun run dev
```

Android:

```bash
cd frontend && bun run build && bun run cap:sync && bun run cap:open:android
```

Переменные окружения клиента: `VITE_API_URL` — адрес API,
`VITE_USE_MOCKS=false` — работать с настоящим бэкендом. Для live reload на
устройстве адрес dev-сервера задаётся в `frontend/capacitor.config.ts`
(`server.url`).
